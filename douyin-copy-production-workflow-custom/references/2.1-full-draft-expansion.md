# 2.1 直投整稿扩写

1. **先拿到完整底稿。** 用下方的91轮直投入口复制固定母会话。用 Gemini 3.1 Pro Preview，只发送完整原稿。不切原稿、不加字数、分段、收尾、CTA、2.5提示词或其他说明。留存原稿、实际请求和原始返回。检查观点覆盖、末句和片尾；仅有 `stop` 不等于完整。如果返回明显截断，保留原始记录并报告，必要时用独立副本按相同方式重试；明确内容过滤时停止该请求。
2. **按直投稿原顺序标出薄处。** 直投整稿负责全篇的开头、观点顺序、叙述口气和结尾总结。逐处记录现有论点、需要补的具体信息和插入点。能讲清楚的部分保留原文。沿用原稿编号和观点数量；小例子、解释和动作落在原观点下面。
3. **其他系统只写局部。** 需要解释、把步骤讲清楚时按内容选2.5或2.8；需要案例时选3.7。使用各系统自己的提示词和会话，把该处前后文、插入点及需要补的内容作为单次任务。输出能插入原稿的局部内容，直接承接当前论点，不加独立开头、总结、CTA或新的整稿编号。已有扩写素材切合插入点时可以复用。插回后去掉重复铺垫和同义复述，保留直投的说话节奏，只对需要的衔接和TTS断句局部修整。
4. **验收和交付。** 默认正文15000至20000中文字，标题、开头、CTA和重复包装不计。沿用2.0的案例保护、黄标与全文TTS断句验收；新增情境和待核实说法标黄。默认交付直投开头连同一份可顺读的完整Word。自然流开头按现行固定CTA替换同功能旧导读；按下方规则保留原直投稿的中段进群CTA，片尾按下方规则处理。用户另行要求时再提供开头备选。验收核对直投观点的相对顺序、插入位置和最终字数。

## 中段进群CTA

- 直投稿已有中段进群CTA时，优先在第一个完整知识点讲完后的自然衔接处保留一次。原位置顺畅就留在原处；原位置打断解释、步骤或案例时，将该段移到就近的知识点结尾，接着讲下一点。
- 沿用该篇直投稿的原CTA，只对必要的前后承接做局部顺句。开头固定CTA照常使用；中段重复出现时保留一处。直投稿没有中段进群CTA时，默认按原正文推进。验收时从前一个知识点读到下一点，核对CTA位置和衔接。

## 片尾收束

- 2.1 成稿默认去掉片尾 CTA。交付时删除直投稿片尾的主页、进群、关注等行动引导，以及仅为该引导铺垫的句子。保留原有正文总结和 Gary 署名，自然结束。
- 验收时检查末尾有无残留引导，例如“我们粉丝群里见”。开头固定 CTA 和按上节保留的中段进群 CTA 照常处理。
