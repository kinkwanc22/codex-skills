# 3.1 Mid-CTA Layer

Read this file after a 3.1 Gemini body passes topic, count, force, length, and zero-CTA checks and before title/opening packaging or Word export.

## Purpose

The accepted 3.1 body must read as a valuable, continuous Gary oral script. Gemini's conversion language from the complete old 2.5 prompt is preserved only in the immutable raw artifact and removed exactly into a separate clean body. Codex then adds only the two required conversion units:

1. one article-native mid CTA;
2. the exact fixed ending.

Do not add scattered soft placements, repeated expertise reminders, or recurring `粉丝群里……` / `我在群里……` sentences. This layer does not change the knowledge route, mother topic, promised count, point order, examples, Gary force band, or substantive wording.

## Default Transformation

1. Save Gemini's raw response unchanged.
2. Run the exact conversion cleaner and save every removed unit verbatim in its deletion manifest.
3. Validate the separate cleaned body for zero residual CTA and all content gates.
4. Add exactly one compact, topic-native mid CTA after useful mechanisms and diagnostic variables are established, normally around 45%-60% of the body.
5. Append exactly: `我是探花Gary，我们粉丝群里见，感谢观看`
6. Do not add any other Codex conversion sentence before, between, or after those two units.
7. Save the CTA and ending in the insertion manifest for Word highlighting and unified validation.

Do not send this layer back to Gemini.

## Mid-CTA Requirements

- Write it from the article's actual mechanism, evidence, failure point, or decision variable.
- Keep the public answer in the body; the CTA may offer diagnosis, review, or the next-step decision, but must not withhold the article's core answer.
- Include one concrete viewer action and one bounded group-delivered value.
- Keep it compact, normally 70-140 Chinese characters in one paragraph.
- Make it read naturally aloud. Avoid route labels, list-like fragments, broken clauses, stacked nouns, and generic `有问题进群` wording.
- Do not fabricate a named student, result, screenshot, volume claim, or verified group event.
- Do not add a new mechanism, operation, case, conclusion, or promised result.

## Word Highlight Output

- Default 3.1 Word: highlight only the mid CTA and exact fixed ending in yellow.
- Never highlight source text, Gemini body text, headings, title packaging, opening candidates, risk notes, or backstage labels.
- If the user explicitly asks for an unhighlighted production copy, preserve the highlighted default and export the clean copy separately; validate it with `--allow-no-yellow`.
- Preserve three separate artifacts: immutable Gemini raw, cleaned zero-CTA Gemini body, and final CTA-layer body.

Manifest shape:

```json
{
  "mode": "3.1_mid_cta_only",
  "soft_placements": [],
  "mid_cta": "<one topic-native CTA>",
  "fixed_ending": "我是探花Gary，我们粉丝群里见，感谢观看",
  "highlight_texts": ["<one topic-native CTA>", "我是探花Gary，我们粉丝群里见，感谢观看"]
}
```

## Acceptance Gate

Before export, record and verify:

- `gemini_raw_preserved: true`
- `gemini_raw_conversion_removed: true`
- `gemini_removal_manifest`
- `gemini_clean_cta_free_pass: true`
- `soft_placement_count: 0`
- `mid_cta_count: 1`
- `mid_cta_position`
- `direct_action_placement_count: 1`
- `fixed_ending_preserved: true`
- `highlight_text_count: 2`
- `default_yellow_highlight_applied: true`

Reject and revise when:

- the raw Gemini response is overwritten or conversion deletions are not recorded verbatim;
- the cleaned body retains any CTA, fan-group invitation, account self-introduction, or fixed ending;
- the mid CTA is missing, generic, repeated, oversized, or interrupts the argument;
- any scattered soft placement or repeated self-reference remains;
- deletion or CTA insertion creates a broken sentence, doubled punctuation, unclear subject, or unnatural TTS pause;
- any yellow text is absent from the manifest, any manifest text is not yellow, or source/Gemini text is highlighted;
- any raw, cleaned, or final artifact overwrites another.
