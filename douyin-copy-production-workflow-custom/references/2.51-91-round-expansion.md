# 2.51 扩写

用户明确指定2.51时使用。按普通2.5流程处理，唯一的流程变更是起始会话改为每篇独立复制固定91轮母本。普通2.5及其他调用2.5的既有分支沿用各自会话规则。

1. 按 [普通2.5扩写合同](gemini-expansion.md) 组装当篇完整的现行2.5直接出稿提示词和原稿。保留原稿包装以及2.5已有的当篇输入要求。不要把2.1的仅原稿输入或1.2的单句限字规则用到这里。
2. 用 [91轮直投入口](2.1-full-draft-expansion.md#91轮直投入口) 所列的固定母本、哈希和 Runner。先用 `逐篇扩写.py prepare <本篇独立目录>` 创建副本，再用 `逐篇扩写.py run <本篇独立目录> <本篇完整2.5提示词与原稿文件> --minimum 4000` 发送完整91轮历史及本篇请求。不继承2.1的生成输入、后期拼接或CTA规则。每篇和重试都另建独立副本。保存实际请求、原始返回和验收结果，母本不写回。
3. 沿用普通2.5的字数和语义验收、开头匹配、案例与黄标及Word交付规则。正文最低4000中文字，沿用2.5的篇幅偏好。交付按2.51标识，保留来源与原始模型返回。设置流程时无需自动生成测试稿。
