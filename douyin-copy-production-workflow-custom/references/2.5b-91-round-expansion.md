# 2.5b 直投扩写

2.5b 是原 2.51 分支的新名称。用户指定 2.5b 时执行。普通 2.5 与其他分支各自的会话和提示词规则保持原样。

1. 按 [91轮直投入口](2.1-full-draft-expansion.md#91轮直投入口) 复制固定母本，每篇及重试使用独立副本。用 `逐篇扩写.py prepare <本篇独立目录>` 创建副本，再用 `逐篇扩写.py run <本篇独立目录> <本篇完整原稿文件> --minimum 1` 发送。只发送完整原稿，不加 2.5 提示词、字数、分段、开头、CTA 或收尾要求。保存实际请求、Gemini 原始返回和接口结束原因。
2. 返回后按 [普通2.5扩写验收](gemini-expansion.md) 检查正文完整性、原稿观点和顺序、字数及口播质量。Runner 的 `--minimum 1` 只用于留存本轮返回，正式正文最低 4000 个中文字。遇到短返或截断，保留原始返回并按普通 2.5 的标准判断是否需要重试；重试仍只发原稿。明确内容过滤时停止该请求。
3. 通过正文验收后，沿用普通 2.5 的开头匹配、案例与黄标及 Word 交付规则，标明 2.5b。2.1 整稿局部补写及 1.2 限字规则不适用。
