# 3.5 Dedicated Gary Voice Session

Read this file before every formal `3.5` Gemini expansion.

## Purpose

3.5 keeps a dedicated long-lived Gary voice context so later drafts inherit the accumulated old Gary cadence, judgment, pressure, and interest-sensitive language. This context controls voice only. The current 3.5 builder and frozen source remain authoritative for the exact mother topic, selected count, content line, route novelty, case placement, and natural-rhythm rules.

Never run 3.5 through the mixed default `gemini_session.json`, the routine 2.5 session, or another version's saved session.

The original seed is the June 5 early-B Gary conversation. Do not modify it. The stable 3.5 session begins as a byte-identical copy and then changes only through promoted 3.5 candidate sessions.

## Candidate-Then-Promote Rule

Do not point a formal generation directly at the stable session. For each standalone article or batch:

1. Copy the stable session into the current work package as `gemini_session_35_candidate.json`.
2. Record the stable and candidate SHA-256 hashes before generation.
3. Run the prompt with `--session-file <work-package>/gemini_session_35_candidate.json`. Do not add `--isolated` or `--new-session`.
4. Let the candidate accumulate only responses that pass the current article's mandatory 3.5 gates. Before each attempt, snapshot the candidate. If the output is rejected for truncation, topic/count drift, case failure, backstage leakage, or gross voice failure, restore that pre-attempt snapshot before retrying.
5. Keep the stable session unchanged while the manuscript or batch remains `正文待确认`.
6. Promote the candidate to the stable session only after the user explicitly approves that manuscript or batch's writing quality. Before promotion, save a timestamped backup of the stable session and record the candidate hash, promoted hash, work ID, and approval evidence.
7. If the user rejects the writing quality, do not promote that candidate. Start the rewrite from the last stable session unless the user asks to preserve part of the rejected turn.

This gives a batch continuity while preventing failed or merely generated drafts from becoming permanent Gary style anchors.

## Runner Behavior

The current runner compacts longer saved histories to:

- the system message;
- the first two complete seed user/assistant pairs;
- the four most recent complete user/assistant pairs;
- the current request.

This is intentional. The first two pairs preserve the early Gary voice anchors while recent approved 3.5 turns keep the voice current. Do not manually append whole manuscript libraries or large style packs to the conversation.

## Formal Command Shape

```bash
cd /Users/kin/Documents/Codex/2026-07-02/gemini
./scripts/run_gemini_chat.sh \
  --prompt-file <work-package>/prompt.txt \
  --session-file <work-package>/gemini_session_35_candidate.json \
  --output-file <work-package>/expanded.txt
```

For a retry, rebuild the complete prompt from the same accepted lean frozen source, restore the pre-attempt candidate snapshot, and run the same command shape. A failed body is never used as the next source or retained as voice history.
