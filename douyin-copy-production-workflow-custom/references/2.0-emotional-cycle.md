# 2.0 正文痛点痒点爽点循环

2026-11-10用户要求：文案中轮流、循环触发用户的痛点、痒点、爽点。本条只加入Gary 2.0编排、扩写任务和最终验收，不改变单独调用2.5、2.8、3.7等系统的默认规则。

## 三种情绪在本篇的具体含义

- 痛点：观众正在经历的具体困境、错误动作、付出没有回应及真实代价。写出场景和行为，让人认出自己，不能只说“你很卑微”“你没框架”。
- 痒点：观众想弄清却没想明白的反差、疑问、隐藏原因或判断难点。围绕本篇实际机制制造求知欲，例如“她愿意聊，为什么一直不愿意见面”；在后文兑现答案，不反复卖关子。
- 爽点：通过理解机制和改变动作，获得更清楚的判断、更有效的表达、主动选择与推进机会的具体感受。用前后动作和情境对比承接，保留Gary的力度、欲望和收获感，不只说“提升自己”，也不把他人的回应写成必然受控的结果。

## 编排与扩写

1. 分段计划除原有内容任务/系统/篇幅外，增加情绪安排：本部分承接哪一个观众困境、留下或回答什么问题、用哪个具体动作和变化交付收获。不要为填表另造论点。
2. 痛点、痒点、爽点须在正文中多轮交替出现，不能只集中在开头，随后长篇连续讲理论。可参考“困境与代价→反差疑问→机制与动作→具体变化→下一个相关困境”，也可按原稿先讲反常识或案例结果，再回到问题。整体须有多次循环，不只出现一次；不强制每一自然段三点齐全，不固定字数间隔和同一种顺序。
3. 一个主要观点或相邻观点组完成一轮有内容的情绪推进：先让观众认出问题或产生疑问，再用解释、案例、方法兑现。下一轮尽量换关系阶段、误判、代价或期待，不能复读同一句“越付出越不被珍惜”。原稿的观点、顺序和主题仍为主，不为情绪循环硬拆点数、虚增案例或改变原意。
4. 送Gemini时保留所选系统的完整原提示词、固定旧会话和本篇原稿要求，另附“本篇2.0情绪任务”这一独立任务说明，写明本段的困境/疑问/收获及与前后段的衔接，要求在干货中自然交替呈现。不得把多套系统提示混在一起，或覆盖共享2.5/2.8/3.7提示原件；记录本轮实际发送文本，保留模型raw。
5. 干货、案例与情绪交织，不另加一段煽动性总结给每个观点套壳。无需降低术语、判断力度或改成温和劝告；案例、对白、动作、因果本身就可承担情绪功能。新增故事沿用黄标和事实验收，锁定案例不为本规则重写。
