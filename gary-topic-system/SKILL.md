# Gary 选题系统

只处理选题层。用户说“出选题、换一批题、扩充题库、提取母题后改题、校正标题、检查选题同质化”时使用本技能。标题一旦被用户锁定，后续换新正文交给 `huanxin`；不要在本技能内写正文、匹配开头、调用扩写线路或导出Word。

## 必读资源

每次正式生成或改写选题，完整读取：

- [选题与双账号规则](references/topics.md)
- [当前月度标准与认可锚点](references/topic-standard-2026-09-24.md)
- [强结果调用池](references/strong-result-pool.md)
- [人工校正锚点](references/manual-correction-anchors.md)：每次出题都读取，用其中已确认的表达对照校准，不能依赖当前对话记忆补齐。

用户明确要求“爽点版、带男人爽点、机制＋爽点＋强结果”时，再完整读取[男人爽点调用池](references/men-payoff-pool.md)。默认模式不读取该池。

校正记录区分用户明确认可、否定和助手未获认可的候选；新候选不因被展示而自动成为正向锚点。

月度标准有明确有效期；过期后不得静默沿用，先依据用户最新校正判断是否续用。用户当前回合的明确修改优先于历史规则。

## 跨对话执行与无知识库测试（2026-10-01）

“出选题”即调用本技能；新对话同样读取上述规则和校正，不用交接提示的概括替代完整Skill。不能要求用户每次再强调“按Skill”。

用户明确要求“不读知识库”时，只跳过知识库和机制卡检索，仍执行本技能的模式、母题、数量、强结果和表达要求。此时可用模型已有可靠知识中的机制，不把未经检索的机制写成已读知识卡或已验证效果，不发明效应；拿不准就换熟悉机制。Skill及其规则、校正文件不属于此处禁止读取的内容知识库。若用户还禁止复用已读资料，则不把此前卡片或原稿作为隐性内容来源。此测试不改变通常需要知识检索的默认流程。

交付前核对：数量对应可展开操作；主机制不是泛泛“聊天技巧／互动方法”；结果达到强结果标准；保留指定母题；同批机制与结果组合不重复；表达符合认可锚点。后台记录不等于检查通过，历史未查范围要如实记录。仅在用户要求检查时展示这些判断。

## 三种入口

### 直接生成

先确定账号和题量。可从[已有选题母题](references/topics.md#已有选题母题简化模式可调用)选择方向；用户给出“泡妞与赚钱”等方向时直接沿用。围绕该方向从强结果池选终点，从知识库匹配一个机制，最后确定可以展开的操作数量。不要求每次重新创造母题，也不单独调用男人爽点；强结果本身就是爽点。没有指定方向且无需调用已有母题时，仍可直接按强结果、机制和数量成题。

通常优先从以下现有知识库读取；用户明确无知识库测试时按上方例外执行：

- `/Users/kin/Gary 男性情感/Gary 男性情感/02_B高价值知识/14_全库可调用卡片`
- `/Users/kin/Gary 男性情感/Gary 男性情感/02_B高价值知识/02_心理机制`
- `/Users/kin/Gary 男性情感/Gary 男性情感/02_B高价值知识/11_生物学机制`
- `/Users/kin/Gary 男性情感/Gary 男性情感/02_B高价值知识/12_社会学机制`
- `/Users/kin/Gary 男性情感/Gary 男性情感/02_B高价值知识/13_泡学方法论`

### 两套独立模式

1. **简化模式（默认）**：可沿用用户给定或已有母题，再按`强结果 -> 机制 -> 数量 -> 标题`成题。用户普通地说“出选题、写七条、再来一批”时使用。不要自动加入男人爽点；保留已有选题方向不等于恢复额外母题分析和完整因果证明。
2. **爽点增强模式（显式调用）**：`机制 -> 男人爽点 -> 强结果 -> 数量 -> 标题`。仅当用户明确说“用爽点版、加爽点、调用爽点库”时使用，并读取[男人爽点调用池](references/men-payoff-pool.md)。爽点描述男人先拿到的直接利益或位置变化，强结果负责最终兑现；两者不能只是同义重复。

两套模式互不覆盖。默认模式的校正不删除爽点模式，爽点模式的标题也不能反向改变默认模式。

### 从原稿扩充题库

逐篇提取原稿原本承诺的结果，再为该结果更换机制和操作数量。用户明确要求保留原母题时才锁定母题；否则不让原稿结构阻碍新的机制与强结果组合。

### 人工校正学习

用户手动改标题时，同时保留助手原版和用户原版，提炼本次修改改变了什么：机制位置、数量、强结果、句式强度或删除的弱表达。把精确校正对与可迁移规律追加到[人工校正锚点](references/manual-correction-anchors.md)；新增强结果再同步到强结果池。不能把一次改法硬化成所有标题的固定模板。

## 生成判断

1. **先锁强结果。** 从强结果池选择一个终点；主动倒追、生理欲望、短期框架、女性资源、主动付出成本、离不开、拿下顶美、驯化女人或成为强者都可直接承担爽点。
2. **再匹配一个机制。** 只从心理学、社会学、生物学或PUA方法论选择现有机制。标题阶段不需要写出完整因果链，也不因缺少“大母题”退回重做；机制与强结果能形成可理解的达成关系即可。
3. **再加操作数量。** 数量对应正文将要展开的操作、方式、步骤、节点或用法。默认使用四至八个，内容确实更大时可增加。
4. **直接写标题。** 默认公式允许使用：`怎么样通过【机制】的N个操作，让女人【强结果】`、`利用【机制】的N种方式，让女人【强结果】`。简单清楚优先，不为了显得高级再外挂母题、男人爽点或完整逻辑。
5. **批次去重。** 重点比较机制和强结果的组合；同批不要重复同一个组合。心理学、生物学、社会学和PUA可以按用户要求分配比例。

### 爽点增强模式的附加判断

- 先确定机制，再从爽点池选择一个贴合的男人利益或位置变化，最后接一个更强的终点结果并补充数量。
- 爽点可以是“不缺女人、成为被争取的人、掌控情绪节奏、完成阿尔法重塑”等；最终仍须落到主动倒追、生理欲望、短期框架、女性资源、主动付出、离不开、拿下顶美、驯化女人或成为强者等强结果。
- 标题要把爽点和强结果写成同一条推进线，不机械堆成四段后台字段。若加入爽点后明显变长或与结果重复，优先压缩爽点表达，不改用默认模式冒充交付。

## 交付

用户只要选题时，只输出编号和标题，不附后台机制说明。内部至少保留：

`账号｜选题方向（如使用已有母题）｜主机制及领域｜数量及内容形态｜强结果ID｜历史去重结论`

用户要求检查、对比或学习时，才展示对应后台字段。没有用户授权，不继续写换新稿或扩写稿。
