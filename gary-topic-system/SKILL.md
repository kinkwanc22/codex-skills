# Gary选题：机制 → 随机匹配强结果 → 操作数量 → 标题

用户说“出选题、换一批题、优化选题”时调用。本技能只完成标题；锁定后再交给换新、扩写流程。

## 执行

1. **抽机制。** 运行下方抽选程序，从四类机制索引随机取候选。索引包含心理学、生物学、社会学、PUA各40项，共160项；后续新增机制先核对原卡再加入索引。读取抽中卡片的原文，确定一个具体主机制。索引名称是候选机制，原卡观点仍需核对；无法支撑本题操作就排除重抽。不要把“聊天技巧、互动方法”等泛词当机制，也不要凭习惯挑熟悉效应。
2. **随机匹配强结果。** 程序为每个机制随机排列[强结果池](references/strong-result-pool.md)。按此顺序取第一个能与机制搭配的结果，明显不搭就看下一个；整池都不搭则重抽机制。只判断搭配是否成立，选题阶段不展开完整证明。
3. **定数量。** 在内部列出可区分、可执行的操作关键词，再确定N，不随机凑数。通常4—8个；用户指定数量时按其要求，材料不足则换机制。
4. **交标题。** 固定表达：`通过【具体机制】的【N个操作】，达成【强结果】。` 可以自然写成“通过……的六个操作，让女人主动倒追你”。标题中必须明确出现机制、操作数量和结果。

每批同一主机制只用一次；优先避开最近30条已交付选题用过的机制。程序返回的是候选，不自动算作已交付；排除不合适候选时用`--exclude`重抽。机制别名按同一机制去重，不靠换名称或换结果绕过。

用户指定账号、方向、机制、结果或数量时服从指定条件，只随机抽未指定项。默认面向单身男人的认识、吸引、筛选及前期推进；长期关系只在用户指定时使用。PUA术语需要按明确回应与双方意愿解释，拒绝不当作同意。生物学机制不能被写成能够直接操控他人激素或必然产生结果的操作。

## 可选母题参考

旧版10个选题方向保留在[可选母题参考](references/optional-themes.md)。用户指定方向、要求沿用旧母题或需要补充方向时读取；合适的个别题也可参考。普通出题不必读取，不把母题作为每题或每批的固定步骤。使用时只限定方向，仍按上述机制、随机结果、数量公式执行，不额外堆叠分析或强行加入母题名称。

## 抽选与记录

```bash
python3 scripts/draw_topics.py --count 7 --out /绝对路径/候选.json
```

相对路径以本Skill目录为基准。可加`--domain 心理学`、`--exclude 卡号1,卡号2`；账号或母题限制由执行者结合原卡筛选。抽中后只读对应原卡，不加载整库。原卡根目录默认`/Users/kin/Gary 男性情感/Gary 男性情感`，可用`--knowledge-root`指定实际根目录。

正式交付后，保存本批JSON数组（每项包含`card_id、mechanism、result_id、count、title`），再登记：

```bash
python3 scripts/draw_topics.py --record /绝对路径/本批选题.json
```

使用记录默认在`~/.codex/topic-system/usage.jsonl`，跨对话共用；记录展示过的正式选题，不把用户未确认的标题记为认可锚点。新环境没有历史时明确从本次开始记录，不能声称完整历史去重。`--history`可指定测试或其他设备上的记录路径。

## 输出与检查

用户只要选题时只交编号和标题。内部检查：具体机制已读取；结果来自调用池且匹配；N个操作确实可展开；本批机制不重复。历史文件位于`references/archive/`，仅供用户要求回溯时读取，不参与当前执行，不再叠加额外母题分析、爽点增强或月度句式规则；可选母题仅按上方入口参考。

用户明确“不读知识库”时仍执行本公式；用可靠的已知机制，说明抽选库未使用，不冒充已读取原卡。
