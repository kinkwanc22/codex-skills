# 2.2 大号原稿直接扩写

2026-11-02用户指定：复制完整2.5流程，独立命名2.2；目标8000—12000中文字，正文验收最低8000字，每篇仍从同一完整固定旧2.5会话复制独立副本。

同日完整试跑后用户要求固定：完整旧会话单次扩写→不足8000时同一会话分段扩写与衔接→humanize-copy轻改（采用第二版的术语/口播平衡尺度）→固定模板开头与扩写前原开头二选一→最终验收与Word交付。

用户只说“大号扩写”而未指定版本时，采用综合入口 `../douyin-copy-production-workflow-custom/SKILL.md` 中的2.0大号流程（最终正文至少12000中文字）。明确指定2.2或“大号原稿直扩”才执行本技能原有8000字验收；明确指定2.5、2.8或其他版本时服从指定。只讨论大号选题、分析或修改规则不授权生成稿件。本技能不修改普通2.5或其他账号版本。

## 执行合同

先读 [完整流程](references/workflow.md)。生成必须原样使用 [完整2.2提示词](references/2.2-direct-draft-prompt.txt)，不添加其他版本的生成提示、换芯任务或3.7人设。原稿直扩，不先改母题、观点、方法或记忆点。

- 字数只计实际正文的中文字符，不计标题包装、多版开头、原文附件或制作说明。8000—12000为目标，8000为硬底线；超过12000不单因字数重跑。30分钟是预期量级，不保证时长，实际配音另验收。
- 每篇使用 `scripts/prepare.py` 冻结纯原文、准备完整旧会话副本和完整提示词。原始DOCX先正确提取正文，不能把点赞等导出元数据当正文。
- 按生成的runner参数使用 `scripts/run_full_history.py`，完整发送复制历史、不压缩；每篇只有一个原稿。首次原稿与下一篇从固定基准另复制，同一篇不足字数则按 [分段衔接](references/segmented-expansion.md) 连续使用该篇会话，不重置、不把它串给另一篇。
- 生成后用 `scripts/check_body.py` 做正文中文字符数及固定片尾检查，再按完整流程人工检查母题/数量/原稿工具/案例/CTA/重复。机器通过不等于全文验收。
- 扩写与衔接完成后，固定执行 [humanize-copy轻改验收](references/humanize-acceptance.md)，再对最终正文复核8000字底线。采用用户选定的第二版尺度：有解释作用、自然贴题的术语和抽象词适当保留；不额外堆词加强成已否定的力度版。
- 按 [开头标题合同](references/openings-and-titles.md) 从当前开头skill的正式H/L固定模板中匹配一个，只填变量；另逐字保留扩写前原稿开头，默认共两个备选。不得用原钩子轻改路径冒充固定模板，也不默认交三版。原稿或开头已获用户锁定时优先保留锁定内容。
- 普通交付到 `/Users/kin/工作用（同步）/探花Gary/01_正文待确认/2.2/<批次>`；测试放 `02_测试稿/2.2/<批次>`；导出和确认状态分开。

完整生成提示词与保存的2.5来源快照仍只有流程代号、目标字数、验收字数三处替换。完整历史适配器、同篇分段补充指令、轻改与双开头交付是2.2的独立执行规则，不改写完整生成提示词或普通2.5。
