按“同女主＋同场景＋近似首帧/机位”归为一个视觉组；无法确认身份时保守合并相似场景，不虚称精确人脸识别。同组的不同动作、近景远景、改名、编码或裁切副本不增加轮回名额。文件SHA用于识别文件，不代替视觉分组。发现同组后合并状态，已用标记取并集，不能靠拆组或重新编号刷新名额。

2026-11-02初始化依据为本会话全库盘点及77条可读文件的首帧接触表；属于初步视觉分组，不等于所有素材已通过完整画面、运动和平台检查。成员需在实际取用时复核多点画面及真实区间。浴袍硬排除，其他筛选按用户当前授权；停帧、黑帧、跳切、损坏素材不得为了凑完一轮而强行使用。

## 一轮如何运行

- 每次批量规划都读全库及台账：优先本轮未用的画面组，不局限于最近缓存的七条。
- 同批每组至多一次；先全批分配，再挑组内适合口播情绪、起始动作及实际可用长度的文件。组内成员优先未用，其次最久未用，不固定抽同一成员。
- 用完当前轮所有启用组才允许进入下一轮。跨轮优先避开上一批画面组及上一轮末尾，按最久未用排序；不能许诺库容量不足时仍永远不相邻复用。
- 批次可跨轮：先用本轮剩余组，再从新一轮选择本批尚未出现的组。若请求数量超过可供本批不重复的启用组数，报告具体缺口，不悄悄重复。
- 新增视觉组加入当前轮未用队列，不清空旧记录；新增同组文件只增加候选，不产生新名额。
- 某组所有成员损坏、缺失或无合适区间时，记录原因与时间，暂时禁用该组，不算已用；恢复后重新参与，不以安全审核、时长不匹配等借口循环跳过大量合适组却反复使用少数旧组。
- 已交付并暴露给用户的画面组继续计入使用历史，删稿或改名不重置。预选、抽帧或未交付的失败构建不算完成使用。

## 脚本与交付登记

使用 `scripts/opening_rotation.py`。`plan`锁住单批计划，防止两个任务同时从同一进度选出相同组；它不生成草稿、不把计划假记成已交付。状态写入前自动备份。未完成的活动计划不能被新任务静默覆盖，先读其状态并继续，或确认未交付后取消。

```bash
python3 scripts/opening_rotation.py plan --batch-id 1103-example --count 7 --out /absolute/path/opening-plan.json
```

输出包括视觉组、轮次、候选成员、上次使用和跨轮情况。它只保证轮回分配，不替代语义匹配或实际取用区间检查。若候选不足，修正组成员/禁用状态并重新规划，不绕开台账手选最近七条。

新稿交付前，将每个开头的`rotation_group`、`rotation_cycle`、原始source/SHA和实际使用区间写入制作清单；后台正式草稿已建立并登记后，准备交付映射数组：

```json
[{"group_id":"实际组ID","source_sha256":"所选成员SHA256","draft_path":"/absolute/path/to/draft"}]
```

`draft_path`须实际存在`draft_content.json`，这里只验证后台草稿存在，不宣称前台播放通过。

```bash
python3 scripts/opening_rotation.py commit --batch-id 1103-example --delivery /absolute/path/rotation-delivery.json
```

仅取消未交付计划时使用 `cancel --batch-id ...`，保留取消记录；已提交批次不能用cancel回滚。已暴露给用户的部分交付不得取消成“从未用过”，应先补记其实际使用再重规划。

每批交付记录轮次、画面组和取用成员；只通过“文件不重复”不能宣称“开头视觉换新”。
