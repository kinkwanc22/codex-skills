# 数字人街拍混剪

用户于2026-10-27对齐此结构，并明确要求将“配音前检查并补写中段进群CTA”加入流程。本模式独立于 `jiepai-jianji`、`avatar-hengban-ziranliu` 和 `avatar-shuping-ziranliu`，不修改这些技能的默认行为。普通街拍请求仍走原街拍模式。

## 文案与CTA前置处理

在任何整篇配音、字幕对齐、音频截取、HeyGen提交之前，先完成：

1. 读取用户当次完整文案，检查中段是否已经包含明确的引流进群CTA。不能只因出现“粉丝群”三个字就认为存在CTA，也不能把文末已有CTA误当中段CTA。
2. **中段已有进群CTA：保留原文，不重复添加、不擅自改写。** 标记其完整起止句。
3. **中段没有进群CTA：结合本篇话题、前文痛点与后文内容补写一段自然的进群引导。** 放在中段已经交付部分内容之后的自然转折处，不按全文50%机械插入、不打断一句话、案例关键动作或尚未兑现的开头承诺。
4. 新CTA应说明与本篇相关的进群理由和清楚的进群动作，承接上文并能接回正文；不凭空增加群福利、免费承诺、个人服务保证、限时活动、联系方式或其他用户未提供的权益。长度由语境决定，不套固定长版销售话术。
5. 保留源DOCX及“正文待确认”状态，原开头和其余正文保持原样。补写版本作为独立制作文案保存，记录插入位置、CTA文本和来源（原文保留/新补写）；不要覆写原稿。
6. 以包含中段CTA的最终制作文案生成**同一条完整配音**。中段有CTA时无需再加第二段；用户原文末尾如有CTA则保留，其画面仍按后续街拍规则处理，不额外生成第三次数字人。

用户已授权这一步作为本模式默认流程，无需每次再问是否添加；若存在用户明确锁定文案、禁止增写等当次限制，遵守其限制，不默默绕过。

## 制作链

- 文案及中段CTA处理完成 → `xiangongyun-tts` 生成整篇配音并过滤停顿 → `srt-aligner` 审阅分行、`--keep-lines` 对齐 → 根据当前全文语义锁定两段数字人的起止 → 从同一完整PCM配音精确截取两段 → HeyGen音频驱动 → 下载核验及校正 → 独立街拍混剪草稿 → 前台检查、按用户要求导出。
- 两段数字人分别是“原街拍开头之后的开场口播”和“中段完整进群CTA”，均以当篇语义完整句为边界。不要套横/竖版的“今天我们要聊的是”切点或任何固定秒数。
- 从完整音频按样本数截取对应区间，记录全文SHA256、起止时码、输出SHA256及PCM区间一致性。禁止另把两段文字交给HeyGen配音；两段都必须对应最终整篇主配音。
- 优先使用用户已选且符合成片画幅的数字人造型，两段保持同一人物与选定造型，记录look ID。本独立模式沿用已验收样本，默认16:9/1280×720/30fps；用户当次指定其他分辨率时按其要求。数字人生成优先选720p，画幅匹配，不自行移植竖屏造型或包装。
- 上传截取音频，关闭语音镜像，保留原声节奏。使用当前用户指定的模型；网页独有能力用正式浏览器流程，已有授权与可用上传权限无需重复要求用户人工上传。每段记录唯一任务ID；结果不明时先查原任务，不盲目重提。
- 若网页模型选择与任务标签矛盾，记录二者，不能把数字人生成成功等同于指定后端模型已核实。当前6Turbo与AvatarIII冲突尚未解决。
- 下载后分别核验实际画幅、时长、解码、声音对应与口型；每段独立测量音画偏移，不套其他样本的23ms。只允许补齐少量末端帧差，不用停帧掩盖缺失口播。

## 固定画面顺序

以当前完整配音时间线标记 A/B/C/D：

| 区间 | 画面 |
| --- | --- |
| 0–A | 原街拍开头，沿用该模式开头素材来源与结构 |
| A–B | 数字人开场口播，第一次出场 |
| B–C | 持续街拍正文混剪 |
| C–D | 数字人讲完整中段进群CTA，第二次出场 |
| D–结尾 | 全部使用街拍画面，不再出现数字人 |

完整主配音贯穿全片；数字人与街拍素材自带声音全部静音，仅保留明确指定配音和配乐。A/B/C/D必须与当前稿真实语音及语义边界一致，不能按素材时长反推或裁掉CTA末句。两段数字人之间不再插额外数字人。原街拍开头是本模式已有的开头，不自动加横版品牌片头、竖版齿轮或正文单图。

## 街拍素材、字幕与包装

制作时读取 `jiepai-jianji/SKILL.md` 中**普通街拍**的素材目录、内容画像/语义匹配、源片与开头帧去重、筛选、批次多样性、剪映静音及转场规则。其固定千川CTA、298秒短版、单女主正文单图包装等是其他模式专用，不移植到本模式。

第一段街拍沿用原开头素材池（Windows默认`E:\工作用\视频素材\街拍片段\可用`），后续街拍来自原街拍池，按文案内容匹配场景，在句尾或自然停顿切镜。不是按文件名或纯随机堆叠。原街拍字幕和包装保持，数字人段字幕使用同一全文字幕与时码，不能重复生成第二套声音或错位字幕。

草稿标题显式包含“数字人街拍混剪”，保留主题、日期与本稿实际素材身份记录；不要覆盖原街拍/数字人横竖版草稿。Windows素材与重渲染优先在win-codex执行，Mac本地文案与已选剪映工作流按当前环境使用。

## 检查与状态边界

- 配音前有明确中段CTA，来源与插入位置有记录，未重复添加。
- 时间线只在A–B、C–D有数字人；原开头和D之后确实全部街拍，不漏回数字人。
- 两次口型、声音与原主配音对应，四个衔接处无漏字、重音、黑帧或空隙；CTA完整，结束后自然回街拍。
- 街拍选段与文案匹配，所有视频静音，字幕/包装连贯，素材可读取。脚本写草稿后仍须前台查看，不能只凭JSON报告通过。
- 分别报告文案处理、音频、两段上传/生成/下载、草稿、后台与前台检查、用户验收、播放、导出、上传发布状态。
- 2026-10-27《顶级男人必备的八大内核》独立720p草稿已由用户亲自查看并确认“合格了，保存起来”。复用样本、制作脚本及验收边界时读取 [references/approved-example.md](references/approved-example.md)。用户验收不等于已经导出或发布；本次保存不额外生成、操作剪映或导出。
